栄養バランス判定アプリ
システム構成・デプロイ要約

作成日: 2026年5月14日

アプリ概要

食事の写真を撮るだけで、Claude Vision AIが食材と量を自動認識し、カロリー・主要栄養素・ビタミン10種の1日の推奨量に対する達成率を表示するWebアプリ。食事記録を日付ごとに蓄積・振り返ることができる。

核心の設計方針： 外部の食品データベースAPIを使わず、Claude Vision APIが画像認識・量推定・栄養素計算を1回のAPIコールで一括処理。追加サービス契約不要でシンプルに完結。

ユーザーフロー

1
食事の写真をスマホで撮影（またはギャラリーから選択）
2
アプリに画像をアップロード（ドラッグ&ドロップ / ファイル選択 / カメラ撮影）
3
「解析する」をタップ → Claude が食材名・推定グラム数・栄養素を JSON で返す
4
食材のグラム数を手動修正して「再計算」も可能
5
カロリー・PFC・食物繊維・食塩・ビタミン10種の達成率バーを表示
6
「この食事を保存する」で日付付きで記録。履歴タブで1日ごとに振り返り可能

デプロイまでのプロセスと課題対応

① ローカル起動の問題（port 5000 競合）

問題原因解決策
Error localhost:5000 に接続できない（403） macOS の AirPlay Receiver が port 5000 を占有 Flask のポートを 8080 に変更

② スマホからのアクセス

問題原因解決策
スマホからアクセスできない Flask が 127.0.0.1（localhost のみ）でリッスン host="0.0.0.0" に変更し、LAN上のIPアドレス（192.168.1.105）で接続
「ファイルを選択」でカメラが起動してしまう input に capture="environment" が常時付与されていた 「ファイルを選択」と「カメラで撮影」でボタンを分離し、capture 属性をカメラボタン押下時のみ付与

③ 画像サイズ超過エラー

問題原因解決策
Error image exceeds 5 MB maximum スマホのカメラ写真が Anthropic API の上限（5MB）を超過 JavaScript の Canvas API でアップロード前に 2048px以下・3.5MB以下 にリサイズ

④ クラウドデプロイ（Render）

問題原因解決策
Blueprint でカード登録を求められる PostgreSQL を含む Blueprint はカード情報が必要 Blueprint を使わず Web Service のみ 手動作成。DBは Supabase（無料・カード不要）を利用
Exit status 1 デプロイ失敗 Supabase への接続に SSL が必要 / モジュール読み込み時の init_db() がクラッシュ 接続URLに ?sslmode=require を付加。init_db() を try/except で保護
GitHub push が認証エラー GitHub がパスワード認証を廃止 Personal Access Token（PAT）を発行して認証

⑤ 保存機能のエラー（3段階で解決）

順序エラーメッセージ原因解決策
1回目 The string did not match the expected pattern. iOS Safari で toLocaleDateString("sv") が YYYY-MM-DD 形式を返さず、input[type="date"] へのセットが失敗 todayStr() を getFullYear() + padStart による手動文字列生成に変更。fetch の相対URL（/save）も window.location.origin + "/save" に統一
2回目 [SyntaxError] JSON Parse error: Unrecognized token '<' サーバーが JSON でなく HTML エラーページを返していた。起動時の init_db() が失敗して meals テーブルが未作成のまま INSERT が走り 500 エラー 全 DB エンドポイントを try/except で囲み JSON エラーを返すよう修正。各リクエスト冒頭で init_db() を再実行してテーブル存在を保証
3回目 connection to server at "db.xxx.supabase.co" port 5432 failed: Network is unreachable Render 無料枠が IPv6 に非対応。Supabase の直接接続URL（db.xxx.supabase.co:5432）が IPv6 アドレスに解決されて疎通不可 Supabase の 接続プーラー（Supavisor） の Transaction mode URL（aws-0-ap-northeast-1.pooler.supabase.com:6543）に切り替え。Render の環境変数 DATABASE_URL を更新して解決
教訓： Render 無料枠 + Supabase の組み合わせでは、Supabase の直接接続URLではなく必ず接続プーラー（Supavisor）のURLを使うこと。直接接続は IPv6 解決になりやすく Render から到達できない。

制約・精度について

項目内容
量の推定精度画像からの盛り付け量推定は ±20〜30% 程度の誤差あり。手動修正機能で補完可能
栄養素の精度Claude の内蔵知識に基づく参考値。公式の食品成分データベースとは異なる場合あり
複合料理カレー・シチューなどは食材分解が難しく、料理単位での推定になる
ビタミン推定食品によって含有量のばらつきが大きく（特にビタミンA・Dは食材依存）、誤差が出やすい

⑥ ユーザーログイン機能（パスキー認証）の追加

背景・目的

当初は認証なしで全ユーザーが同一DBを共有する構成だった。複数ユーザーが使えるよう、ニックネーム＋パスキー（WebAuthn/FIDO2）によるログイン機能を追加し、各ユーザーが自分の食事履歴のみ閲覧できるようにした。

認証方式の選定

方式採用理由
パスキー（WebAuthn/FIDO2）採用パスワード不要・スマホのFace ID / Touch IDで完結。フィッシング耐性あり。iOS Safari / Chrome 対応済み
パスワード認証不採用パスワード管理の手間・ハッシュ保存・リセット機能など実装コストが高い
OAuth（Google等）不採用外部サービス依存・設定手順が複雑

追加した APIエンドポイント

エンドポイント処理内容
POST /api/auth/register/beginニックネームを受け取り、WebAuthn 登録オプション（challenge等）を生成してセッションに保存
POST /api/auth/register/completeブラウザからの credential を検証し、users・credentials テーブルにINSERT。セッション開始
POST /api/auth/login/beginニックネームから該当credentialを検索し、WebAuthn 認証オプションを生成
POST /api/auth/login/completeアサーションを検証し、sign_count を更新。セッション開始
POST /api/auth/logoutセッションをクリア
GET /api/auth/me現在のログイン状態とニックネームを返す

認証フロー（登録 / ログイン）

【登録フロー】
ブラウザ                          サーバー（Flask）
  │  POST /api/auth/register/begin（nickname）
  │ ─────────────────────────────────────►
  │  ◄─ registration options（challenge）──
  │
  │  navigator.credentials.create(options)
  │  → デバイス認証（Face ID / Touch ID）
  │
  │  POST /api/auth/register/complete（credential）
  │ ─────────────────────────────────────►
  │  verify → users + credentials INSERT
  │  ◄─ {ok: true, nickname} ─────────────
  │  → セッション開始・アプリ画面表示

【ログインフロー】
  │  POST /api/auth/login/begin（nickname）
  │ ─────────────────────────────────────►
  │  ◄─ authentication options（challenge）─
  │
  │  navigator.credentials.get(options)
  │  → デバイス認証（Face ID / Touch ID）
  │
  │  POST /api/auth/login/complete（assertion）
  │ ─────────────────────────────────────►
  │  verify + sign_count 更新
  │  ◄─ {ok: true, nickname} ─────────────
  │  → セッション開始・アプリ画面表示

変数名説明ローカルのデフォルト

制約： WebAuthn は HTTPS 必須（localhost は例外）。Render は自動で HTTPS を提供するため本番環境では問題なし。SECRET_KEY を env var で固定しないと Render 再起動のたびに全ユーザーがログアウトされる。

⑦ インストール時のトラブル（Python環境）

問題原因解決策
ModuleNotFoundError: No module named 'webauthn' conda 環境や複数の Python が混在し、webauthn をインストールした Python と実行時の Python が異なる 仮想環境（venv）を作成して統一：python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt
No matching distribution found for flask==3.1.0 venv が Python 3.7 で作成され、Flask 3.x の要件（Python 3.9+）を満たさない CommandLineTools の Python 3.9 を明示指定して venv を再作成：/Library/Developer/CommandLineTools/.../python3 -m venv venv
教訓： macOS は Python 2.7 / 3.7 / 3.9 等が混在しやすい。開発時は必ず python3 -m venv venv で仮想環境を作り、python3 --version で 3.9+ であることを確認してから始める。
